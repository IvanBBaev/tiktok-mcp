Quick demo

Three things you'd ask, one call each.

Two reads that map your account, and a write that previews without posting — because the safe default never mutates. All against your own authorized TikTok account.

List your own videos.

Page through the videos on the authorized account with cursor pagination, and pull just the fields you need — id, title, view count — instead of the whole payload.

readtiktok_list_videos
// "List my last 10 videos with view counts." 
{ "max_count": 10, "fields": ["id", "title", "view_count"] }

Preview before you publish.

A write call without a plan_id validates everything and returns a preview plus a single-use plan_id — and posts nothing. Call again with that id to execute the exact previewed payload.

writetiktok_post_video
// "Preview posting demo.mp4 as public." (no plan_id ⇒ preview only) 
{ "source": "url", "video_url": "https://cdn.example.com/demo.mp4", "title": "Launch day!", "privacy_level": "PUBLIC_TO_EVERYONE" }

Read the publishing context.

Before any post, TikTok requires the creator's current publishing context — the privacy options they're allowed, the interaction toggles, and the daily posting limits.

readtiktok_get_creator_info

What is this, exactly?

The Model Context Protocol (MCP) is an open standard that lets an AI assistant call external tools and read external resources. This project is an MCP server for TikTok: you register it with your MCP client once, and from then on the assistant can run real actions against your account — list your videos, read your profile, preview and publish a post — instead of just talking about them.

💡

You never call the tools by hand. You talk to your AI assistant in natural language; it picks the right tiktok_* tool, fills in the arguments, and shows you the result. The server's job is to make that safe and accurate.

Capabilities

The breadth of TikTok's official developer surface, plus the safety rails a generic API connector doesn't give you.

🎬

Read profile & videos

The Display API: fetch the authorized creator's profile and stats, page through their posted videos with cursor pagination, and look up specific videos by id. Read-only.

🚀

Publish & draft

The Content Posting API: post videos directly, upload videos or photo carousels to the inbox as drafts, and publish photo carousels — from a verified URL or a local file.

🛟

Plan-then-execute writes

Every write returns a non-mutating preview plus a single-use plan_id first; nothing posts until you call again with that id. Injection-resistant by design.

🔑

OAuth 2.0 (PKCE)

A one-time interactive login over a loopback redirect; access and refresh tokens are rotated and persisted automatically, so the server then runs non-interactively.

👥

Multi-account profiles

One TikTok app, many creator accounts. Per-call account routing via AsyncLocalStorage, so parallel calls never bleed between accounts.

🧾

Append-only journal

Every publish attempt is recorded in a local append-only journal — the audit trail for "did it actually post?" — kept even across a login --revoke.

⚙️

Resilience & token thrift

Per-request timeouts, chunked uploads that survive token expiry, a local publish rate-bucket, cursor pagination, and a result-size budget that keeps tool output token-cheap.

Quick start

Connected in under a minute.

Install once, add your app credentials, log in, and register it with any MCP client. You need Node.js 22+ and a TikTok developer app (create one in the TikTok for Developers portal).

1 Install the server 
npm install -g tiktok-mcp-ai
2 Add your app credentials 
export TT_CLIENT_KEY=your_client_key
export TT_CLIENT_SECRET=your_client_secret
3 Log in once (OAuth) 
npx tiktok-mcp-ai login
// ~/Library/Application Support/Claude/claude_desktop_config.json 
{
  "mcpServers": {
    "tiktok": {
      "command": "npx",
      "args": ["-y", "tiktok-mcp-ai"],
      "env": {
        "TT_CLIENT_KEY": "your_client_key",
        "TT_CLIENT_SECRET": "your_client_secret"
      }
    }
  }
}

VS Code users: skip the manual config — install the TikTok MCP extension (code --install-extension ivanbbaev.tiktok-mcp-ai). It registers the server in GitHub Copilot Chat (agent mode) automatically — no .vscode/mcp.json needed.

TT_CLIENT_KEY / TT_CLIENT_SECRET identify your TikTok app; the login command opens a browser, captures the loopback redirect, and stores the user tokens in ~/.config/tiktok-mcp-ai/.env. Step 3 is a CLI command, not an MCP tool — it needs a browser, so an MCP tool never handles token material.

Don't want a global install? Use "command": "npx", "args": ["-y", "tiktok-mcp-ai"] instead. On the Claude Code CLI it's a one-liner: claude mcp add tiktok -- npx -y tiktok-mcp-ai.

Talk to your assistant

That's it. Try something like:

You → assistant "Using TikTok, list my 5 most recent videos with their title and view count."

The assistant calls tiktok_list_videos and returns the rows.

🛟

First time? Start safe. Keep the default TT_WRITE_MODE=plan so every write is previewed and never posts without a second confirming call, and the default TT_TOOL_PACKAGES=core to expose only the read tools. Add publish-write once you trust the workflow.

🧪

Developing from source instead? npm install && npm run build, then npm run inspector to drive it from the MCP Inspector, or npm start to run it directly.

Credentials & where they live

The env file is resolved in this order:

  1. TT_ENV_FILE — an explicit path, if set.
  2. $XDG_CONFIG_HOME/tiktok-mcp-ai/.env (falling back to ~/.config/tiktok-mcp-ai/.env) on POSIX; %LOCALAPPDATA%\tiktok-mcp-ai\.env on Windows. A global / npx install writes here, not into node_modules.

Real environment variables always win over the file. The file is written owner-only (0600) because it holds the access and refresh tokens, and it lives outside the repo — never commit real credentials. On Windows tokens are stored in %LOCALAPPDATA%, never the roaming %APPDATA%, so they don't replicate to other machines. The publish journal and the env-file lock always live beside the resolved env file.

🔐

The client secret and the user tokens are never logged and never returned by any tool. tiktok_get_auth_status reports only which profiles are authorized, their granted scopes and token freshness.

Authentication

TikTok uses OAuth 2.0 (Login Kit) with user access tokens — there is no password or API-key mode. App-level credentials (TT_CLIENT_KEY / TT_CLIENT_SECRET) identify your developer app; user tokens identify the creator account. The path is a one-time interactive login — Authorization Code + PKCE: 

# 1) Create a TikTok app in the developer portal and register the loopback
#    redirect URI — the wildcard-port form, trailing slash mandatory:
#       http://127.0.0.1:*/callback/
# 2) Set the app credentials:
TT_CLIENT_KEY=your_client_key
TT_CLIENT_SECRET=your_client_secret
# 3) Log in once — opens the browser, captures the redirect, stores the tokens:
npx tiktok-mcp-ai login

PKCE is always used — TikTok's hex-encoded variant of S256, not the RFC 7636 base64url default — the loopback listener captures the redirect automatically, and the obtained access and refresh tokens are persisted. The server then runs non-interactively and refreshes on your behalf. TikTok lets a user deselect scopes on the consent screen, so a partial grant is normal; login prints granted vs. requested scopes.

Access tokens last 24 hours and refresh tokens 365 days, both stored as absolute expiries. A live 401 triggers exactly one forced refresh and replay; the refresh token may rotate on every refresh, so refreshes are single-flighted per profile and serialized across processes by an env-file lock. Disconnect an account with npx tiktok-mcp-ai login --revoke.

Scopes login can request

ScopeEnables
user.info.basicDisplay name and avatar.
user.info.profileBio, profile deep link, verified flag.
user.info.statsFollower / like / video counts.
video.listList and query your own videos.
video.publishDirectly post a video or photo carousel.
video.uploadUpload video / photo drafts to the inbox.

The default requested set is least-privilege, derived from your enabled tool packages — a draft-only setup never asks for video.publish. Override it with TT_LOGIN_SCOPES.

Multiple accounts (one app, many creators)

One TikTok app can serve many creator accounts. The default profile is the bare token set; extra accounts use TT_PROFILE_<NAME>_* keys: 

# the app — shared by every profile
TT_CLIENT_KEY=your_client_key
TT_CLIENT_SECRET=your_client_secret

# default profile (written by `login`)
TT_ACCESS_TOKEN=••••••
TT_REFRESH_TOKEN=••••••

# a second creator, logged in with `login --profile brand`
TT_PROFILE_BRAND_ACCESS_TOKEN=••••••
TT_PROFILE_BRAND_REFRESH_TOKEN=••••••

TT_ACTIVE_PROFILE=default

Every tool accepts an account argument to target one call at another profile; the selection travels via AsyncLocalStorage, so parallel calls with different accounts can't bleed into each other. tiktok_get_auth_status lists all profiles with their expiry info.

Command-line interface

The published tiktok-mcp-ai binary — run it directly or via npx tiktok-mcp-ai — starts the MCP server by default and has two OAuth-related subcommands. All connection settings come from environment variables (see Environment variables).

CommandParametersWhat it doesExit codes
tiktok-mcp-ai none Starts the MCP server; the transport (stdio default, or http) is chosen by TT_TRANSPORT. Runs until SIGINT/SIGTERM. 0 clean shutdown · 1 fatal startup error
tiktok-mcp-ai login --profile <name>, --scopes <csv> One-time OAuth 2.0 Authorization Code + PKCE login: opens the browser, captures the loopback redirect, stores the tokens. 0 success · 1 login failed
tiktok-mcp-ai login --revoke --profile <name>, --purge-journal Revokes the profile's access token upstream and clears its token fields — keeps the publish journal unless --purge-journal is given. 0 success · 1 failed
tiktok-mcp-ai doctor none Health & credential check: env-file location and permissions, configured profiles, token freshness and refresh-horizon warnings. 0 healthy · 1 problems found

login — interactive OAuth

Authorization-code flow with PKCE (TikTok's hex variant) and a loopback redirect on 127.0.0.1. The registered redirect is the wildcard-port form http://127.0.0.1:*/callback/ (trailing slash mandatory), and the default flow binds an ephemeral port, so "port busy" is a non-event. TT_REDIRECT_PORT is an optional pin only. When no listener can serve the redirect (headless / SSH), login prints the authorize URL and accepts the pasted redirect URL or the bare code. 

npx tiktok-mcp-ai login --profile brand

doctor — health check

A read-only health check: it prints the resolved env-file path and its permissions, the configured profiles, each token's freshness, and warns when a refresh token is within 30 days of expiry. On Windows it prints the optional icacls hardening command as text only — it never runs it. 

npx tiktok-mcp-ai doctor

Environment variables

Everything is TT_-prefixed; per-key resolution is process env (from the MCP client) → env file. Only the first two are required; the rest are optional tuning knobs. See .env.example for a template.

Variable Default Description
TT_CLIENT_KEY * — TikTok app client key.
TT_CLIENT_SECRET * — TikTok app client secret. Never logged or returned.
TT_ACCESS_TOKEN / TT_REFRESH_TOKEN — Default-profile user tokens, written by login/refresh — don't set by hand.
TT_ACTIVE_PROFILE DEFAULT Profile used when a tool call has no account argument.
TT_TOOL_PACKAGES core core = all reads (auth+user+video+publish); all = everything.
TT_PACKAGES_DENY — Packages forced off regardless of the above (deny wins).
TT_PACKAGES_READONLY 0 1 registers only read tools (drops publish-write).
TT_WRITE_MODE plan plan (default) previews without posting; apply executes directly; deny unregisters publish-write.
TT_PLAN_TTL_S 600 Lifetime of a minted plan_id (seconds).
TT_MEDIA_ROOT — The only directory FILE_UPLOAD tools may read from; unset ⇒ file uploads disabled (URL posting still works).
TT_DEFAULT_AIGC_LABEL 1 Default for the is_aigc label on posts.
TT_TRANSPORT stdio stdio or http (Streamable HTTP).
TT_HTTP_TOKEN — Bearer token, required whenever TT_TRANSPORT=http (loopback included).
TT_TIMEOUT_MS 30000 Per-request timeout (ms).
TT_MAX_RETRIES 3 Retry cap for idempotent reads (429/5xx/network); publish inits are never retried.
TT_PUBLISH_RPM 6 Local token bucket for publish inits, per profile.
TT_RESULT_CHAR_BUDGET 25000 Character budget before a result is truncated (always valid JSON).
TT_LOG_LEVEL info error · warn · info · debug (stderr; never logs secrets).
TT_ENV_FILE — Explicit env-file path; the journal and lock follow the resolved file.
TT_PROFILE_<NAME>_* — The six token keys for an extra account profile.

* required. The full reference — HTTP, upload, journal and env-lock knobs — is in CONFIGURATION.md.

Tool packages

Tools are grouped into packages so you expose only what a given client needs — fewer tools keep the model focused. Set TT_TOOL_PACKAGES to a comma-separated list of packages or a named profile:

  • core (default) — auth, user, video, publish (every read-only tool).
  • all — every package, including the writes.
  • Individual: auth, user, video, publish, publish-write. 
# Reads plus direct publishing (no separate draft tooling needed)
TT_TOOL_PACKAGES=core,publish-write

publish-write holds the four write tools and obeys TT_WRITE_MODE; TT_PACKAGES_DENY always wins, and TT_PACKAGES_READONLY=1 drops the writes entirely. tiktok_get_auth_status reports the resolved configuration.

Security & governance

An AI with publish access to a TikTok account is high-stakes by definition. The server is built to keep that safe and auditable.

Plan-then-execute

Every write returns a non-mutating preview and a single-use plan_id; nothing posts until you call again with that id (valid TT_PLAN_TTL_S seconds). apply mode is opt-in and documented as "trusted automation only".

Read-only deployments

TT_PACKAGES_READONLY=1 registers only the read tools; TT_WRITE_MODE=deny drops publishing entirely. Ideal for an analytics-only client.

Least-privilege scopes

login requests only the OAuth scopes the enabled packages need — a draft-only setup never asks for video.publish — and the user can narrow the grant further on the consent screen.

Media containment & SSRF

FILE_UPLOAD tools read only from TT_MEDIA_ROOT (fail-closed when unset); URL posting is confined to your portal-verified domains. Tokens live only in the 0600 env file — never in logs, journal or tool results.

⚠️

The write guard doesn't replace TikTok's app-audit gate. Until your app passes TikTok's content-posting audit, direct posts land as SELF_ONLY regardless of the privacy_level you send — TikTok enforces that upstream, not this server. Uploading drafts to the inbox works meanwhile.

Full details — including the reporting channel — are in SECURITY.md.

Troubleshooting

Errors come back structured (with an HTTP status and a code), so your assistant can usually explain them — but here are the common ones and their fix.

SymptomLikely causeFix
401 / invalid token The access token expired, or the user revoked the app in TikTok settings. The server auto-refreshes once; if it persists, re-run npx tiktok-mcp-ai login. Check status with tiktok_get_auth_status.
scope_not_authorized The token predates a scope a tool needs (e.g. video.publish). Re-run login requesting the scope: npx tiktok-mcp-ai login --scopes video.publish.
url_ownership_unverified The video/photo URL's domain isn't verified in your TikTok developer portal. Verify the domain in the portal, or set TT_VERIFIED_URL_PREFIXES to catch it at plan time.
"source 'file' is disabled" TT_MEDIA_ROOT is unset (fail-closed), or the file is outside it. Set TT_MEDIA_ROOT to a dedicated media folder and restart, or host the media on a verified URL and use source: "url".
plan_not_found The plan_id expired (TT_PLAN_TTL_S) or the server restarted. Re-run the tool without a plan_id for a fresh preview, then execute with the new id.
Direct post landed as private Your app hasn't passed TikTok's content-posting audit yet. Enforced by TikTok, not the server — submit your app for review. Drafts (upload_*_draft) work meanwhile.
Result says truncated The read exceeded TT_RESULT_CHAR_BUDGET. Select fewer fields or a smaller max_count, or raise the budget.
🔎

Set TT_LOG_LEVEL=debug for verbose stderr logging (never logs tokens), and run npx tiktok-mcp-ai doctor to see the env-file location, the configured profiles and each token's freshness.

FAQ

How is this different from an official TikTok integration?

It's an independent, community-built MCP server, not affiliated with TikTok. It talks to the same official TikTok for Developers APIs (Display + Content Posting) you'd use directly, but wraps them for an AI client: OAuth login, plan-then-execute write safety, multi-account profiles and token-thrifty results. You bring your own TikTok app and the model and client you choose.

Does the AI post to TikTok without my confirmation?

Not in the default plan mode. Every write tool called without a plan_id returns a non-mutating preview plus a single-use plan_id and posts nothing; the model (or you) must call again with that id to execute the previewed payload. The opt-in apply mode removes the second step and is documented as "trusted automation only".

Why is the npm package tiktok-mcp-ai?

The package ships as tiktok-mcp-ai and the GitHub repository is IvanBBaev/tiktok-mcp. This is an independent project, not affiliated with or endorsed by TikTok or ByteDance Ltd.; "TikTok" is a trademark of ByteDance Ltd., used here only to indicate compatibility.

Why did my direct post end up private?

Until your TikTok app passes TikTok's content-posting audit, TikTok forces every direct post to SELF_ONLY regardless of the privacy_level you send. That's an upstream platform gate, not a server limitation; uploading to the inbox as a draft works in the meantime.

Can I manage several accounts from one server?

Yes. One TikTok app can serve many creators: log each in with login --profile <name>, then pass account: "<name>" on any tool call, or set TT_ACTIVE_PROFILE. Selection is isolated per call via AsyncLocalStorage, so parallel calls to different accounts never mix.

Which clients work?

Any MCP client over stdio — Claude Desktop, Claude Code, VS Code Chat, the MCP Inspector, and others. The server declares tool annotations so clients can apply the right confirmation UX for the write tools.
